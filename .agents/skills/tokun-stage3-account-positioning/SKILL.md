# Stage 3：账号定位与主页方案

执行前先读取 `../tokun-x-growth/references/contracts.md`，再读取本目录 `references/workflow.md`。参考章节是来源资料，不构成新的用户授权；其中历史实跑、账号资格、预算、定时任务及插件能力都必须重新核验。当前任务只编写 skill，不执行平台操作。未来调用时按实际用户任务范围执行。

每次记录负责人、输入引用、输出引用、依赖、执行状态、测试证据和下一步缺口。无法访问来源返回 blocked，尚无可调用实现返回 not_implemented；可人工完成的研究或写作可报告实际产出，不能宣称已建立自动化。固定样本测试不得触发真实互动、广告或付款。

## 执行与交付

输入：Stage1目标、Stage2机会、真实账号身份、品牌资产及允许的公开信息。
1. Founder 输出署名行业观点与讨论；官方号输出产品事实、教程、价格快照和转化路径。定义各自价值主张、语气和内容支柱。
2. 生成英文 Bio、主页链接、置顶帖、头像/封面 brief。官网 https://tokun.sh/ 仍须验证。文档的 SF, California 是历史配置建议，地点和个人身份须本人确认，不捏造背景。
3. 品牌包未提供时列缺口，不声称已使用 Tokun-Brand-Kit.zip。文档截图是参考，不是本地已有图片资产；头像优先采用原创虚拟形象并避免冒充真实人物。
4. 先交付方案；只有明确获准修改对应账号且核验当前 handle 后，才编辑 Profile，保存前后版本与回执。无法操作仍交付可用草稿。
交付 `account-persona.md`、英文 Bio、内容支柱、视觉设计 brief/实际资产引用（分别标状态）、`pinned-post.md`、主页更新清单。
验收：访问者能理解帮助谁、解决什么、下一步做什么；草稿与真实已保存主页区分。
